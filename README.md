# SysWatch

Лёгкий монитор Windows: какие процессы грузят CPU, память, диск и сеть, куда они подключаются и какие домены запрашивают. Работает фоном и почти ничего не потребляет.

**Статус:** этап 2. Агент собирает данные, окно `SysWatch` показывает их: живые графики, таймлайн, сеть, карточки программ, события.

## Как устроено

```
SysWatch Agent (служба, LocalSystem)
 ├─ ETW kernel ── запуск/завершение процессов, TCP/UDP-трафик по процессам
 ├─ ETW DNS ───── какой процесс какой домен разрешил (→ кэш IP → домен)
 ├─ Sampler ───── CPU / RAM / дисковый I/O по процессам раз в 5 с (Win32, без исключений)
 └─ Flusher ───── раз в минуту: свёртки → SQLite одной транзакцией + замер своей стоимости
```

Сырые события на диск не пишутся, только агрегаты за минуту. Процесс идентифицируется объектом, а не PID: Windows переиспользует PID.

## Окно

```powershell
# от администратора; агент должен работать в другом окне или как служба
dotnet run --project src\SysWatch.App
```

| Экран | Что показывает |
|---|---|
| Сейчас | живой список программ (CPU, память, диск), топ за час, стоимость мониторинга |
| Таймлайн | загрузка системы по минутам, тепловая карта программ, снимок выбранной минуты |
| Сеть | потоки «программа → домен», все адреса, новые за сегодня |
| Карточка программы | графики, подпись exe, процессы с командными строками, куда подключалась |
| События | запуски, завершения, DNS-запросы |

Устройство: WinForms + WebView2, внутри React (`src/ui`). Запросы к `https://syswatch.local/api/*` перехватываются в C# и обслуживаются из SQLite агента — без HTTP-сервера и открытых портов. Живые данные окно снимает само, раз в секунду и только пока открыто.

Интерфейс уже собран в `src/SysWatch.App/wwwroot`. Пересобрать после правок в `src/ui`:

```powershell
cd src\ui
npm install
npm run build      # кладёт сборку в src/SysWatch.App/wwwroot
npm run dev        # разработка в браузере на мок-данных
```

## Требования

- Windows 10 1809+ или Windows 11, x64
- .NET 10 SDK (`winget install Microsoft.DotNet.SDK.10`)
- Права администратора (ETW ядра)

## Быстрый запуск (без установки службы)

В терминале **от администратора**:

```powershell
cd C:\GIT\SysWatch
dotnet run --project src\SysWatch.Agent
```

В режиме разработки сводка печатается каждые 15 секунд, данные пишутся в `C:\ProgramData\SysWatch\dev`. Пример сводки:

```
── SysWatch 22:41:15 ──────────────────────────
Система:   CPU  12.4%   RAM   61%
Топ CPU:
  chrome.exe                     3.10%   RAM    412 MB
Топ сеть (↑/↓):
  chrome.exe                     120.4 KB /   2.1 MB
Соединений: 84   DNS-запросов: 37   новых процессов: 2   завершилось: 1
Агент:     CPU 0.08%   RAM 38 MB   GC 4 MB   ETW 950 соб/с   потеряно 0   запись 3 мс
```

Остановка: `Ctrl+C`.

**Главное, что проверяем на этом этапе:** строку `Агент:`. Цель — CPU агента меньше 0.5%, RAM меньше 50 MB, `потеряно 0`.

## Установщик

Обычная установка — файл `SysWatch-Setup-<версия>.exe`: мастер установки, ярлыки, удаление через «Приложения» Windows. .NET ставить не нужно — он внутри.

- **Скачать:** раздел Releases на GitHub (публикуется автоматически по тегу `v*`) или артефакт `SysWatch-Setup` последней сборки во вкладке Actions.
- **Собрать самому:** `.\scripts\build-installer.ps1` → `installer\Output\SysWatch-Setup-<версия>.exe` (Inno Setup поставится через winget при первом запуске).
- **Новая версия:** поменять `<Version>` в `Directory.Build.props`, закоммитить и поставить тег: `git tag v1.0.1; git push --tags`.

Установщик не подписан цифровой подписью, поэтому Windows SmartScreen при первом запуске покажет «Неизвестный издатель» → «Подробнее» → «Выполнить в любом случае».

## Установка для разработки (одна команда)

```powershell
# PowerShell от администратора
cd C:\GIT\SysWatch
.\scripts\install.ps1
```

Что произойдёт:
- агент станет службой Windows `SysWatchAgent` и будет стартовать вместе с системой;
- SysWatch будет запускаться в трей при входе в Windows (задача планировщика, без окна UAC);
- в меню Пуск появится ярлык «SysWatch».

Клик по иконке в трее открывает окно. Закрытое окно полностью выгружается из памяти, в трее остаётся только иконка; подсказка на ней показывает процессор, память и состояние агента. Выход — правый клик по иконке.

После изменений в коде просто запусти `install.ps1` ещё раз — он остановит старую версию и поставит новую.

```powershell
.\scripts\uninstall.ps1               # удалить (история остаётся)
.\scripts\uninstall.ps1 -RemoveData   # удалить вместе с историей
```

## Данные

`C:\ProgramData\SysWatch\hot\YYYY-MM-DD.db`: один SQLite-файл на день, хранится 7 дней. Открыть можно в [DB Browser for SQLite](https://sqlitebrowser.org/).

| Таблица | Что внутри |
|---|---|
| `process` | процессы: pid, время создания, имя, путь, командная строка, родитель, время выхода |
| `proc_1m` | по минутам: CPU (мс), пик частной памяти, чтение/запись диска, сеть ↑/↓ |
| `conn_1m` | по минутам: процесс → IP:порт (+ домен), байты ↑/↓, число подключений |
| `dns` | DNS-запросы: процесс, домен, ответы |
| `system_1m` | общая загрузка CPU и памяти |
| `self_1m` | стоимость самого агента |

Пример: кто больше всех качал сегодня.

```sql
SELECT p.image, SUM(m.net_rx)/1048576.0 AS mb_in, SUM(m.net_tx)/1048576.0 AS mb_out
FROM proc_1m m JOIN process p ON p.id = m.proc_id
GROUP BY p.image ORDER BY mb_in DESC LIMIT 10;
```

## Настройки

`src/SysWatch.Agent/appsettings.json`, секция `Agent`:

| Параметр | По умолчанию | |
|---|---|---|
| `SampleIntervalSeconds` | 5 | опрос CPU/RAM/IO |
| `FlushIntervalSeconds` | 60 | сброс на диск |
| `BackgroundMode` | true | низкий приоритет CPU/IO/памяти |
| `EcoQoS` | true | энергоэффективные ядра (Windows 11) |
| `StoreCommandLines` | true | хранить командные строки (бывают секреты) |
| `RetentionDays` | 7 | сколько дней хранить |

## Ограничения

- Содержимое HTTPS не видно. Видно процесс, IP, порт, домен (через DNS) и объём.
- Если программа использует свой DNS (например, DNS-over-HTTPS в браузере), домен для её соединений может быть пустым.
- Процессы короче 5 секунд видны (ETW), но их CPU может не попасть в замер.
